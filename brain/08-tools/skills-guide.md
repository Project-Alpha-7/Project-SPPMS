# Skills: when and how

Type `/name` in a new session. (m) = manual only. Brain rules beat skill advice.

## Design and motion
- `/mobile-native`: phone fixes. Run first (15px inputs make iOS zoom).
- `/break-ui`: stress-test tables and tracking with worst-case data.
- `/emil-design-eng`: polish buttons, tiles, cards, dialogs.
- `/find-animation-opportunities`: list where motion helps (read-only).
- `/animate`: build one animation (menu, toast).
- `/choreograph`: several moving together (timeline, KPI cards).
- `/gestures`: swipe and drag (sidebar, sheets).
- `/apple-design`: spring and sheet feel.
- `/improve-animations`: audit all motion, get a plan.
- `/animation-performance`: fix jank (blur header).
- `/remove-animations`: cut needless motion.
- `/animation-vocabulary`: name an effect.
- `/review-animations` (m): strict motion review.
- `/prototype` (m): compare UI variants.
- `/pick-ui-library` (m): choose a library.
- `/learn-taste` (m): save design rules.
- `/ask-emil` (m): which skill to use.

## Code quality
- `/ponytail`: minimal-code mode (backend work). "stop ponytail" ends it.
- `/ponytail-review`: review a change.
- `/ponytail-audit`: whole-repo audit before the demo.
- `/ponytail-debt`: list deferred shortcuts.
- `/ponytail-help`: reference.

## Security
- `/skill-inspector`: check any new skill before installing.
